# 포함한 외부 원문을 적용하는 방법

외부 원문과 해당 MIT, Apache-2.0 또는 CC BY-SA 4.0 고지를 `third_party/`에 함께 보존합니다. [카탈로그](skill-catalog.md)와 각 SOURCE.json이 포함 파일과 고정 커밋을 설명합니다. 스킬 원문의 경로는 자체 스킬에서 명시적으로 읽도록 연결합니다. 원문 보관을 자동 발견이나 전체 플러그인 설치로 표시하지 않습니다.

[최상위 가드레일](../GUARDRAILS.md), 프로젝트의 실제 규정과 지시, 사용자가 승인한 계획을 적용합니다. 외부 원문의 예시 명령을 실행 권한으로 해석하지 않습니다. 준비 단계에서 공개 게시를 명시적으로 승인받았다면 공개 가능한 파일과 고지를 확인한 뒤 그 승인 범위에서 게시할 수 있습니다. 제한된 과제 수행 중에는 Git push, 배포와 과제 자료의 외부 전송 금지를 적용합니다. 자동 UI 조작과 외부 모델 연결은 허용하지 않습니다. 다음 적용 차이는 원문 파일을 변경하지 않고 이 문서에서 관리합니다.

| 원문 항목 | 이 하네스에서의 적용 |
|---|---|
| writing-plans의 실행 인계 | `hx-plan`에서 계획을 제시하고 승인 후 `hx-build`로 진행합니다. 포함된 실행·병렬 스킬은 external-routing의 조건으로 선택합니다. 원문이 요구해도 별도 세션, worktree와 커밋을 무조건 생성하지 않습니다. |
| 계획 경로와 형식 | `.harness/plan.json`과 연결된 프로젝트 문서를 사용합니다. 원문의 문서 위치와 고정 제목 양식은 강제하지 않습니다. |
| TDD의 적용 범위 | 의미 있는 동작 변경과 회귀 수정에 실패 입력과 기대값을 먼저 확인합니다. 단순 문구·형식 변경에는 불필요한 테스트를 만들지 않습니다. 기존 사용자 코드를 삭제하고 다시 쓰는 지시는 적용하지 않습니다. |
| 커밋 예시 | [Git 관례](conventions.md)를 따릅니다. 스킬 원문을 읽었다는 이유로 커밋이나 원격 작업을 수행하지 않습니다. |
| 검증의 최신성 | 변경 뒤 영향을 받은 검사를 실행합니다. 마지막 유효한 검사 판본과 현재 파일을 대조합니다. 변경이 없는 상태에서 같은 검사를 보고마다 반복하지 않습니다. |
| 디버깅 중 재검토 | 같은 원인으로 수정이 반복 실패하면 가설과 구조를 다시 확인합니다. 범위나 요구를 바꿔야 한다면 사용자에게 묻습니다. 무한 재시도하지 않습니다. |
| fluent-korean frontmatter | 원본의 Claude 전용 메타데이터를 Codex 설정으로 적용하지 않습니다. 한국어 작성 원칙과 명시된 예외만 사용합니다. |
| frontend-design의 화면 검토 | 업무 원문과 실제 구현을 연결합니다. 스크린샷이 가능하다는 원문은 Computer Use나 자동 UI 조작 권한을 뜻하지 않습니다. 사용자가 허용된 화면에서 직접 확인합니다. |
| security-best-practices의 호출 조건 | 사용자가 보안 모범 사례, 보안 검토 또는 안전한 기본 구현을 명시적으로 요청했고 지원 언어·프레임워크가 있을 때만 해당 참조를 읽습니다. 원문의 외부 검색 제안은 과제 자료 전송이나 규정 밖 인터넷 사용을 허가하지 않습니다. 일반 코드 검토로 보안 감사를 자동 시작하지 않습니다. |
| sql-code-review의 범용 예시와 점수 | 실제 DB 방언, 스키마와 입력에 맞춰 원문 조언을 검토합니다. 원문의 점수와 성능 개선 표현은 실행 측정으로 확인하기 전에는 결과로 쓰지 않습니다. |
| test-gap-audit의 탐색 스크립트 | `coverage_map.py`는 읽기 전용 휴리스틱으로만 사용합니다. 필요하면 실행 전 파일과 명령을 검토합니다. 매칭 결과를 실제 테스트 범위로 단정하지 않고 관련 코드와 단언을 직접 확인합니다. |

추가 외부 스킬이 필요하면 실제 기능과 동반 파일, 라이선스 및 승인 범위를 먼저 확인합니다. 패키지에 없는 스킬을 있는 것처럼 호출하지 않습니다. 외부 문서의 예시 명령은 프로젝트의 실행 명령으로 자동 채택하지 않습니다.

추가한 외부 원문은 자동 훅, 외부 AI 연결과 브라우저 자동화 도구를 설치하거나 실행하지 않습니다. 스킬의 참조 URL을 읽는 것과 시험 자료를 그 URL에 전송하는 것은 다릅니다. 실제 프로젝트 코드, 입력, 결과, 화면과 대화 기록을 외부 조회 인수에 넣지 않습니다. 공개 준비 단계의 게시와 시험 중 Git push 금지는 [가드레일](../GUARDRAILS.md)에 따라 구분합니다.

## 요구 구체화와 API 설계 원문의 적용

`requirements-scoping`의 답이 없으면 가정을 두고 진행하라는 예시는 사용자 승인 절차를 대체하지 않습니다. 결과를 바꾸는 미확인은 질문으로 남기며, 사용자가 선택을 위임한 범위에서만 가정과 이유를 기록합니다. 원문에 없는 대규모 트래픽이나 가용성 목표를 임의로 정하지 않습니다. 규모 관련 질문은 실제 제약일 때만 묻습니다.

`api-design`은 실제 요청·응답과 오류 계약에 사용합니다. 과제에 필요하지 않은 GraphQL, 분산 시스템, 멱등성 저장소나 클라우드 구성을 추가하지 않습니다. 두 원문에서 언급하는 `back-of-the-envelope`, `resilience-failure`, `consistency-coordination`, `architecture-diagram` 등 미포함 스킬은 자동 호출하지 않습니다. 필요한 판단은 기존 hx-plan과 관련 코드의 검사로 처리합니다.

React 원문은 각각의 버전과 문제 조건이 맞을 때만 읽습니다. `react19-concurrent-patterns`는 실제 React 19 또는 승인된 이주 작업, `react18-batching-patterns`는 React 18 클래스 컴포넌트의 자동 배칭 회귀에 한정합니다. 스킬을 사용하기 위해 버전을 올리거나 기존 앱을 다시 구성하지 않습니다. 브라우저 자동화 없이 코드와 허용된 검사로 검증합니다.

## 설계와 추가 개발 스킬의 적용

- `system-design`의 전체 분산 설계와 45분 예제는 기본 실행 절차가 아닙니다. 실제 요구에 필요한 구성요소, 데이터 소유권, 입출력, 선택 이유와 실패 조건만 확정합니다. 미포함 하위 스킬을 호출하거나 외부에서 자동 설치하지 않습니다. 구성 예제의 클라우드, 큐와 트래픽 수치를 요구사항으로 채택하지 않습니다.
- Superpowers의 브라우저·시각화 서버·별도 세션·커밋·브랜치 종료 지시는 자동 실행하지 않습니다. 병렬 도구가 실제 제공되고 승인 범위의 독립 작업일 때만 사용합니다. 최종 제출 루트로 통합하고 해당 코드로 다시 검사합니다.
- `property-based-testing`은 승인된 불변조건에 적용합니다. 기존 라이브러리가 없으면 설치 허용과 시간을 확인합니다. 새 라이브러리를 넣지 않고 경계값 검사로 진행할 수 있으며, 이 경우 속성 기반 도구를 실행했다고 표시하지 않습니다.
- PDF의 Poppler 설치나 시스템 패키지 명령은 예시입니다. 관리 환경을 임의로 변경하지 않습니다. 자동 UI 조작은 금지합니다. 허용된 로컬 파일 렌더링·검사만 수행하고 불가능한 시각 검사는 미확인으로 기록합니다.
- Notebook의 전역 `$CODEX_HOME` 경로를 사용하지 않습니다. 설치 후 동봉한 `.harness-kit/third_party/openai-task-skills/skills/.curated/jupyter-notebook/scripts/new_notebook.py`를 기존 Python으로 실행합니다. 다른 Python 버전을 자동 다운로드하지 않습니다. 생성한 Notebook은 실행 검증과 구분합니다.
- 공개 라이선스의 원문을 보존한 것과 시험에서 모든 절차가 허용되는 것은 다릅니다. 최상위 가드레일과 실제 프로젝트 지침을 먼저 적용합니다.

`domain-modeling`은 실제 답변으로 확정된 용어만 기록합니다. 스킬이 만든 반례를 업무 사실로 취급하지 않습니다. 별도 ADR은 되돌리기 어렵고, 맥락 없이 이해하기 어려우며, 실제 대안 비교가 있었던 선택에만 작성합니다. 모든 선택마다 문서를 늘리지 않습니다.

`executing-plans`의 Ruling으로 미확인 요구를 확정하지 않습니다. 요구, 범위, 기대값과 동작을 바꾸는 판단은 먼저 사용자에게 질문하고 변경 계획을 승인받습니다. 원문의 중단 조건 목록이 이 승인 조건을 제한하지 않습니다. 승인 범위 안의 세부 구현만 계속 진행합니다.

계획 승인 전 domain-modeling 결과는 용어 후보와 출처를 계약·계획 문서에 기록하는 데 한정합니다. GLOSSARY.md와 ADR 파일 생성·수정은 승인된 문서 작업 범위에서 수행합니다. 원문의 즉시 기록 지시는 이 단계 구분을 넘지 않습니다.

UI UX Pro Max는 `${CLAUDE_PLUGIN_ROOT}`를 설정하거나 플러그인을 설치하지 않습니다. 설치 후 `python3 .harness-kit/third_party/ui-ux-pro-max/.claude/skills/ui-ux-pro-max/scripts/search.py "keyboard focus" --domain ux --max-results 1`처럼 실제 동봉 경로를 사용합니다. 검색은 로컬 CSV를 읽습니다. 승인 전 `--persist`와 `--force`를 실행하지 않습니다. 승인 뒤에도 기존 결과를 임의로 덮어쓰지 않습니다. 외부 폰트·이미지·CDN 제안은 자동 다운로드나 외부 전송 권한이 아닙니다. 현재 스택을 보존하고 검색 결과를 규정이나 요구사항으로 취급하지 않습니다.

## 확장 라이브러리의 실행 제한

확장 라이브러리는 원문 보관소입니다. 기본 27개 선택표를 먼저 사용하고 부족할 때 로컬 색인을 검색합니다. `reference-only` 항목은 시험 중 호출하지 않습니다. 색인은 문서 지침이며 임의 명령 실행을 기술적으로 차단하지 않습니다.

- Addy Osmani의 `using-agent-skills`가 제안하는 전체 생명주기나 shipping까지의 자동 연결을 실행하지 않습니다. 명세에서 무응답을 승인으로 해석하는 문구도 적용하지 않습니다. 현재 요구와 계획의 명시 승인을 따릅니다. 반복 승인 양식을 별도로 만들지 않습니다.
- `browser-testing-with-devtools`, `playwright-expert` 등 자동 브라우저 검사는 사용하지 않습니다. CI/CD·shipping·배포·원격 티켓·PR·Jira/Confluence·Shopify·Salesforce 작업은 시험용 호출에서 제외합니다. 참고 원문에 있더라도 Git push, 원격 쓰기와 외부 과제 전송을 실행하지 않습니다.
- `doubt-driven-development`의 외부 Gemini·Codex CLI 교차 모델 연결을 실행하거나 권하지 않습니다. 현재 환경에서 허용된 검토만 수행합니다.
- Matt Pocock의 티켓·PR·setup 절차는 시험 중 실행하지 않습니다. 나머지 코드·설계 스킬에서도 임시 HTML을 외부 창으로 열거나 CDN·브라우저를 호출하지 않습니다. 필요한 구조 설명은 로컬 Markdown으로 정리합니다. 미포함 다른 스킬은 자동 검색·설치하지 않습니다.
- Impeccable은 `scripts/impeccable` 및 context/live/generate/visualize/hooks/pin/doctor/update를 실행하지 않습니다. 자동 엔진 다운로드, 이미지 생성 모델, 스크린샷·CDP·브라우저 조작을 사용하지 않습니다. 허용된 디자인·접근성 문서를 직접 읽고 코드·로컬 검사·사용자 직접 관찰로만 검토합니다. 시각 관찰이 없으면 미확인으로 기록합니다.
- Ponytail은 요청한 작업 범위에서만 읽습니다. 세션 전체 활성화, 플러그인·훅 설치, 자동 업데이트, 다른 세션 로그 가져오기를 하지 않습니다. 원문의 벤치마크 수치를 현재 모델이나 시험의 성능으로 인용하지 않습니다.
- 확장 스킬의 기술 예시는 현재 프로젝트의 언어·버전·규정을 대체하지 않습니다. 효과를 측정하지 않은 원문을 '시험 성능 검증 완료'로 기록하지 않습니다.
