# 확인한 동작과 설계 근거

이 문서는 1.7.0의 확인 범위를 설명합니다. 실제 시험 환경의 실행이나 성적을 검증한 기록은 아닙니다.

## 실행으로 확인한 것

| 검사 | 확인한 결과 |
|---|---|
| Python 단위 검사 | 82개가 통과했습니다. 승인 전 실행 거부, 승인 판본 변경, 파일 변경 후 근거 무효화, 검사 실패, 설치 충돌과 기존 파일 보존을 포함합니다. |
| 합성 실행 3개 | CSV 집계, 로컬 HTTP, 지연 주문 예제에서 실제 검사를 실행했습니다. 회귀 실패와 복구를 확인했습니다. |
| 인계 경계 | 자동 검사가 통과해도 handoff.md가 없거나 비어 있으면 준비 완료로 표시하지 않습니다. 문서 내용의 정확성은 자동 인증하지 않습니다. |
| 수동 화면 경계 | 자동 HTTP 검사를 통과해도 화면 관찰 요구는 미확인으로 남습니다. 자동 UI 조작은 실행하지 않았습니다. |
| 스킬 사용 | 별도 에이전트가 CSV 정책 질문, SQL 중복 집계와 문서 오타의 합성 요청에서 필요한 스킬을 직접 읽었습니다. SQL 사례는 SQLite에서 합계 7이 조인으로 11이 되는 문제와 행 보존 후 7을 확인했습니다. |

스킬 사용 검사는 명시적 파일 읽기와 행동 확인입니다. Codex CLI가 새 스킬을 자동 발견하는지 확인한 검사가 아닙니다. 자동 발견이 안 되면 [첫 실행 절차](../BOOTSTRAP.md)에 따라 파일을 직접 읽습니다.

재현 명령은 저장소 루트에서 실행합니다. 합성 실행에는 테스트용 승인 문구가 있으며 실제 과제에 사용하면 안 됩니다.

```sh
python3 -m unittest discover -s tests -v
python3 tools/smoke_demo.py
```

## 적용한 절충

명세는 업무 요구를 정하고, 테스트는 그 요구의 관찰 가능한 결과를 확인합니다. 모든 문구 수정에 TDD를 적용하지 않습니다. 계산, 분기와 회귀 수정에 실패 입력을 먼저 정합니다. 시험 시간에는 스킬 개수와 문서 길이보다 필수 경로의 실제 동작을 우선합니다.

별도 MCP 서버, 외부 모델 연결이나 자동 훅이 없어도 실행할 수 있게 Python 표준 라이브러리를 사용했습니다. 그 결과 브라우저 화면을 자동 검증하거나 임의 셸 명령의 네트워크 접근을 차단하는 기능은 없습니다. 스킬 12개와 30개의 성능 비교 실험도 하지 않았습니다.

승인 기록은 실제 대화의 인용을 보존하는 로컬 기록입니다. 사용자 신원을 인증하지 않습니다. 요구 원문이 빠졌거나 기대값을 잘못 정했는지는 사람이 읽을 수 있는 계획과 독립 검토로 대조해야 합니다. 파일과 검사 해시가 일치하는 사실만으로 과제 전체의 정답을 보증하지 않습니다.

## 1.6 보완

설치 예고는 복사 없이 충돌과 생성 경로를 검사합니다. 같은 조건의 이전 검사 기록을 검증하고 상태 전이와 변경 파일을 보여 줍니다. 미작성 인계 양식은 완료로 판정하지 않습니다. 상태 안내는 남은 시간과 필수 요구 결과를 반영하고 사용자가 명시한 다음 작업은 보존합니다.

[Python과 JavaScript 검사 레시피](test-recipes.md)는 기존 도구로 여러 기술의 검사를 연결하는 방법을 설명합니다. 순수 Node 예시를 실제 실행해 올바른 기대값의 통과와 잘못된 기대값의 실패를 확인했습니다. 문서에 표시한 실행하지 않은 예시는 검증 결과에 포함하지 않습니다.

## 1.7 외부 스킬 연결

요구 구체화와 API 설계, React 버전에 맞는 상태 처리 원문 4개를 더 포함했습니다. 총 외부 스킬은 12개입니다. 자체 hx-plan과 hx-specialist의 조건별 경로로 연결합니다. 새 원문의 미응답 가정 진행과 미포함 스킬 호출은 로컬 승인 절차를 넘지 않도록 제한했습니다. 기존 프로젝트의 React 버전을 바꾸지 않습니다.

원본 파일 48개의 SHA-256을 출처 기록과 대조했습니다. 원문과 라이선스를 보존한 사실은 해당 스킬을 모든 과제에서 실행했다는 뜻이 아닙니다. 실제 작업에서 선택한 원문과 적용 결과는 handoff에 기록합니다.

## 1.8 공통 개발 단계와 로컬 검색

외부 스킬은 27개입니다. 요구 탐색, 설계와 데이터 모델, 승인된 계획 실행, 코드 리뷰, 독립 작업 분담, PDF·Notebook, 속성 기반 테스트, 업무 용어 및 UI 지침 검색을 작업별 선택표에 연결했습니다. 원문의 외부 전송, 별도 세션, 임의 정책 확정과 전역 경로 지시를 그대로 실행하지 않도록 적용 차이를 기록했습니다.

기존 단위 테스트 82개와 합성 예제 3개를 실행해 통과했습니다. Notebook 생성 스크립트로 실험용 파일을 생성하고 JSON 구조·제목·7개 셀을 다시 읽었습니다. 이는 Notebook 전체 계산 실행 검증과 다릅니다. UI UX Pro Max의 로컬 검색은 합성 키워드로 실행해 실제 지침 반환을 확인했습니다. 원본 파일 해시와 선택표 경로도 확인했습니다.

스킬을 실제로 모두 사용한 과제 성능 비교는 수행하지 않았습니다. PDF 패키지·Notebook 커널과 시험 플랫폼은 별도 환경 조건이며, 자동 UI 조작과 실제 제출은 검증하지 않았습니다.

## 1.9 확장 라이브러리

외부 SKILL.md 153개를 포함합니다. 동일 출처·판본·내용의 중복 1개는 색인에서 별칭으로 처리합니다. 서로 다른 원문 152개는 기본 27개, 기술별 조건부 자료와 실행 제한 자료를 포함합니다. 원본 파일 881개의 SHA-256과 색인에 등록한 경로를 대조했습니다.

검색 도구는 네트워크나 스킬 실행 없이 동봉 JSON만 읽습니다. 제한 항목과 중복 항목의 기본 검색 제외, 한국어 검색어 연결과 결과 없음 처리 검사를 추가했습니다. 스타와 제작자 평판은 조사 범위를 정하는 신호이며 실행 품질 보증이 아닙니다. 새 확장 스킬 전체의 효과를 비교 검증하지 않았습니다.
