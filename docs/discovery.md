# 업무 담당자에게 요구를 확인하는 방법

업무 담당자와 대화할 수 있으면, 프로젝트 원문에서 찾지 못한 업무 맥락을 확인합니다. 담당자가 없거나 질문 채널이 제공되지 않으면 원문과 기존 자료만 사용합니다. 가상의 답변을 만들지 않습니다. 질문 예시는 [질문 양식](../templates/stakeholder-questions.md)에, 실제 답변의 기록 형식은 [답변 기록 양식](../templates/stakeholder-notes.md)에 있습니다.

## 질문을 준비합니다

원문에 적힌 목표, 사용자, 입력, 처리, 출력, 예외와 제약을 먼저 표시합니다. 결과를 바꾸는 빈칸만 질문으로 바꿉니다. 질문마다 그 답이 바꿀 화면, 처리 규칙 또는 검사 결과를 적습니다. 실제 업무 사례 하나를 먼저 확인합니다. 연관된 질문은 한 번에 2~3개만 묻고, 답변을 읽은 뒤 다음 질문을 고릅니다.

담당자에게 현재 업무, 대표 사례와 실제 사용하는 자료를 물어봅니다. 이어서 누락, 중복, 권한 부족과 처리 실패 중 중요한 예외를 확인합니다. 시간이 제한되면 반드시 처리할 경로와 제외할 경로의 우선순위를 묻습니다. 정책을 결정하는 사람이 따로 있다면 그 사람과 결정 시점을 확인합니다. 마지막에는 작은 입력 하나와 관찰 가능한 기대 결과를 요청합니다.

## 답변 상태를 구분합니다

| 상태 | 기록 방법 |
| --- | --- |
| 원문 명시 | 파일과 위치, 짧은 인용을 적습니다. 해석이 필요한 부분은 별도로 표시합니다. |
| 담당자 진술 | 실제 질문과 답변, 발화자, 기록 위치와 시각을 적습니다. 진술의 결정 권한을 확인합니다. |
| 확정 | 결정 권한이 있는 주체가 해당 정책을 명시적으로 확인한 근거를 적습니다. |
| 가정 | 답을 받지 못한 상태에서 임시로 둔 선택과 그 영향을 적습니다. 확정된 요구로 쓰지 않습니다. |
| 충돌 | 서로 다른 원문과 답변을 함께 보존하고, 결정 주체에게 차이를 확인합니다. |
| 미확인 | 질문을 보내지 않았거나 답을 받지 못한 사항을 그대로 적습니다. |

담당자나 대화형 AI의 답변은 출처가 있는 진술입니다. 답변자에게 정책 결정 권한이 있다는 근거가 없으면 그 답변만으로 정책을 확정하지 않습니다. 대화형 AI가 실제 사람의 발언을 대신한다는 주장도 하지 않습니다. 다른 원문과 충돌하면 한쪽을 조용히 삭제하지 않습니다. 개인정보와 접근 정보를 질문이나 기록에 불필요하게 넣지 않습니다.

## 요구와 검증을 연결합니다

1. 원문 또는 실제 답변에서 확인한 한 가지 동작을 요구 ID `R1`로 적습니다. 출처가 프로젝트 안의 UTF-8 파일에 있을 때 [계약 형식](contract.md)의 `source.path`와 `source.quote`로 연결합니다. 대화 기록을 파일에 보존할 수 없는 경우에는 존재하지 않는 파일 경로나 인용을 만들지 않습니다. 원래 대화 위치를 답변 기록에 남기고 계약 작성 방법을 확인합니다.
2. 대표 입력, 경계 입력과 기대 결과를 업무 근거에서 독립적으로 정합니다. 현재 코드 출력을 기대값으로 복사하지 않습니다. 결과에서 제외하는 입력이 있으면 제외 이유와 처리 전후에 달라지는 값을 확인합니다.
3. 계획의 `acceptance`에는 사용자가 확인할 수 있는 결과를 적습니다. 남은 정책 질문은 `questions`에 영향, 선택지와 결정 주체를 적고 열린 상태로 둡니다.
4. 각 요구를 검사 ID `C1` 또는 사람이 직접 확인할 항목에 연결합니다. 명령의 종료 0, 수동 관찰과 기능의 기대값 비교를 구분합니다. 실행 전에는 검사를 통과로 적지 않습니다.
5. 이해한 목표, 주요 사례, 예외, 제외 범위와 미확인을 짧게 재확인합니다. 답변과 원문이 바뀌면 계약과 계획의 현재 판본을 다시 검토합니다. 구현에는 [계획과 승인 절차](methodology.md)를 적용합니다.

이 절차는 질문과 기록을 돕습니다. 질문 목록과 자동 검사는 실제 업무 요구가 빠지지 않았다고 보증하지 않습니다.
