# 프로젝트 작업 관례

[최상위 가드레일](../GUARDRAILS.md)을 먼저 적용합니다. 시험 전 범용 도구의 승인된 공개 게시와 시험 중 구현을 구분합니다. 시험 중에는 Git push와 문제·작업 자료의 우회 외부 전송을 금지합니다. 이 관례는 프로젝트의 실제 요구와 기존 저장소 지침 안에서 적용합니다. 규칙의 개수나 문서의 길이는 완료 기준이 아닙니다. 작은 기능이 실제로 동작하고 그 근거를 읽을 수 있어야 합니다.

| 주제 | 권장 행동 | 확인할 한계 |
|---|---|---|
| 지침 순서 | 프로젝트 원문과 적용되는 저장소 지침을 먼저 읽고, 이 툴킷의 계약과 스킬을 그에 맞춥니다. | 외부 템플릿이 프로젝트의 요구를 바꾸지 않습니다. |
| 파일과 구조 | 기존 언어, 실행 명령, 파일명과 의존성을 먼저 사용합니다. 새 파일은 필요한 경로에만 만듭니다. | 합성 예제의 파일명을 실제 프로젝트에 강제하지 않습니다. |
| 예외 처리 | 원문이 정한 실패 입력에 관찰 가능한 결과를 줍니다. 예상 밖 오류는 재현에 필요한 정보를 남깁니다. | 넓은 예외 처리로 오류를 조용히 버리거나 거짓 성공을 반환하지 않습니다. |
| 데이터 | 원본 ID, 단위, 빈 값, 정렬과 중복 기준을 확인합니다. 정제는 원문 규칙을 확인하고 원본을 보존한 채 수행합니다. | 도구의 표본 조사나 전체 행 중복을 업무 키 중복으로 확대하지 않습니다. |
| 의존성 | 설치된 환경과 기존 잠금 파일을 우선합니다. 새 패키지가 필요하면 이유와 호환 버전을 확인합니다. | 의존성 추가가 검증 시간을 늘릴 수 있습니다. |
| 테스트 | 입력과 기대 결과가 드러나는 이름을 쓰고 요구사항 ID의 검사와 연결합니다. 실패한 입력으로 수정 전후를 비교합니다. | 테스트 이름이나 종료 코드만으로 동작을 보증하지 않습니다. |
| 실패 로그 | 명령, 입력, 기대값, 실제 결과와 재검사 결과를 짧게 남깁니다. | 비밀값과 무관한 전체 로그를 기록에 복제하지 않습니다. |
| 사용자 화면 | 화면이 있으면 성공, 빈 상태, 오류와 로딩을 실제 환경에서 확인합니다. | `observe`는 사용자 자기보고입니다. 도구가 화면 관찰을 인증하지 않습니다. |
| 문서 정본 | 원문이 기준이고 계약은 파생 명세입니다. `next`와 `decisions`는 작업 상태, evidence는 실행 근거입니다. | `spec`과 `brief` 출력을 별도로 저장했다면 그 사본은 자동 갱신되지 않습니다. |
| 병렬 작업 | 독립 작업에 서로 다른 파일의 소유를 정합니다. 공통 파일과 전체 검사는 통합 담당자가 확인합니다. | 환경이 병렬 작업을 지원하는지 먼저 확인합니다. 같은 파일을 동시에 고치지 않습니다. |

구현 실패를 계약의 기대값 완화로 해결하지 않습니다. 원문 해석 오류나 공식 추가 설명이 확인된 경우에만 근거를 남기고 계약과 검사를 수정합니다. `decision --actor candidate`는 사용자가 실제로 내린 판단에만 사용합니다. 이 필드와 `observe`는 자기보고이며 도구가 실제 참여를 인증하지 않습니다.

## 로컬 Git 기록

기본 확인 명령은 읽기 전용 `git-check`입니다. 이 명령은 로컬 변경 경로와 공백 오류를 보고합니다. Git 저장소가 아니라면 그 상태를 보고하며 새 저장소를 만들지 않습니다. 커밋이 필요한 프로젝트에서는 변경 파일을 검토한 뒤 필요한 경로만 명시적으로 추가합니다.

```sh
git status --short
git diff -- path/to/file
git add -- path/to/file
git diff --cached -- path/to/file
git diff --cached --check
git commit -m "feat(summary): preserve raw IDs for R1"
```

이 명령은 선택적 로컬 커밋의 예시입니다. 무관한 파일을 `git add .`로 함께 추가하지 않습니다. 툴킷은 `git init`, 자동 커밋, 브랜치 전환, 전역 설정 변경, 원격 조회나 Push를 수행하지 않습니다. `feat`와 `fix`는 기능과 수정에 쓰고, 필요한 경우 `test`, `docs`, `refactor`, `chore`를 사용합니다. 커밋 본문에는 실제 이유와 실행한 검사만 선택적으로 적습니다. 커밋 형식은 기능 검증을 대신하지 않습니다.

## 중단과 축소

새 도구를 찾는 일은 현재 요구를 해결하는 데 필요할 때만 합니다. 설치가 실패하거나 지침 자동 발견이 안 되면 기존 코드와 테스트 명령으로 진행합니다. 같은 오류가 반복되면 실패를 재현하고 원인 가설을 다시 점검합니다. 남은 시간이 부족하면 새 의존성과 선택 기능을 멈추고 핵심 동작, 현재 검사 결과와 산출물 경로를 확인합니다. 완료되지 않은 요구는 그대로 보고합니다. 작업을 더 진행하지 않을 때 `close`로 로컬 상태를 닫을 수 있으며, 닫힌 상태는 새 작업을 자동으로 시작하지 않습니다.

전체 명령은 [WORK_API](../WORK_API.md)에 있습니다. 작업 흐름은 [개발 방법](methodology.md)에 있습니다.
