# 한국어 기술 문서 작성 기준

목표는 사용자가 동작과 근거를 한 번에 이해하고 재현하게 하는 것입니다. 한국어 문장은 ASD-STE100의 명료성 원칙을 참고해 짧고 직접적으로 씁니다. 이는 영어 통제언어 표준의 인증이나 정식 준수 판정이 아닙니다.

## 실제 적용 원문

코드 구현과 수정, 그 결과를 설명하는 개발 문서에는 [fluent-korean 코딩용 원문](../third_party/fluent-korean/plugins/fluent-korean/output-styles/fluent-korean.md)을 끝까지 읽고 적용합니다. 일반 조사나 비개발 설명에는 [비코딩용 원문](../third_party/fluent-korean/plugins/fluent-korean/output-styles/fluent-korean-not-coding.md)을 적용합니다. 원문의 예시와 예외를 이 문서의 요약으로 대체하지 않습니다. 라이선스와 판본은 [SOURCE.json](../third_party/fluent-korean/SOURCE.json)에 있습니다.

## 문장 규칙

- 한 문장에는 한 가지 핵심 사실이나 행동을 담습니다. 주체, 대상, 조건과 결과가 필요한 문장에서는 그 성분을 생략하지 않습니다.
- 행동은 구체적인 동사로 씁니다. 본문은 조사와 서술어가 있는 완성된 문장으로 끝냅니다. 표의 짧은 항목명과 제목은 예외입니다.
- 같은 개념에는 같은 이름을 씁니다. 기술 용어는 처음 등장할 때 역할을 짧게 설명합니다. 정확한 함수명, 파일 경로와 검사 ID는 유지합니다.
- 조건이 있으면 행동 앞에서 설명합니다. 여러 명령은 실행 순서대로 나눕니다. 성공과 실패에서 관찰할 결과를 함께 적습니다.
- 계획, 구현된 동작, 실제 실행 결과, 사용자 자기보고와 미확인을 구분합니다. 실행하지 않은 명령은 예시로 표시합니다.
- 막연한 수식, 근거 없는 최상급과 인위적인 대비 표현을 줄입니다. 중간점으로 문장 성분을 나열하기보다 조사와 서술어로 관계를 설명합니다.
- 코드, 코드 주석, 로그, 커밋 메시지와 원문 인용에는 프로젝트 관례와 원본 표기를 유지합니다. 문체를 맞추려고 증거 내용을 바꾸지 않습니다.

## 문서별 책임

| 문서 | 담당하는 내용 |
|---|---|
| README | 목적, 시작 명령과 필요한 환경을 설명합니다. |
| contract.json | 원문 인용과 기대 결과, 구현·검사 연결을 관리합니다. |
| plan.json | 범위, 작업 순서, 수용 기준과 미해결 질문을 관리합니다. |
| state.json과 evidence | 승인 근거, 실제 선택과 실행 결과를 관리합니다. |
| handoff.md | 현재 상태를 설명하고 코드·명세·근거의 위치와 다음 작업을 연결합니다. |

`handoff.md`에 전체 로그와 원문을 반복해서 붙이지 않습니다. 현재 상태와 필요한 사실을 요약하고 상세 근거를 연결합니다. 템플릿은 작성 구조이며 그 존재가 완료를 뜻하지 않습니다.

## 완료 전 검토

먼저 문서와 실제 코드, 명세, 명령 출력 및 파일 판본을 대조합니다. 수치, 담당 주체, 검증 범위와 실행 방법이 맞는지 확인합니다. 그다음 한국어 문장을 별도로 읽고 생략된 주체와 조건, 모호한 동사를 고칩니다. 문장을 고친 뒤 사실과 기술적 의미를 다시 대조합니다.

실행 안내는 실제로 재현합니다. 링크가 현재 파일을 가리키는지 확인합니다. 사용자에게 보여 주지 않은 화면이나 받지 않은 답변을 직접 확인으로 쓰지 않습니다. 자동 검사는 문서의 링크와 일부 기계적 근거를 확인할 수 있지만 설명의 정확성과 사용자의 이해를 인증하지 못합니다.
