# 과제에 맞는 최소 도구 선택

원문과 실제 입력 파일을 먼저 확인합니다. 아래 표는 읽을 문서를 고르는 기준입니다. 모든 스킬을 한꺼번에 읽거나 패키지를 설치하지 않습니다. 기존 기술과 잠금 파일을 유지합니다. 계획 승인 전에는 원문 조사와 계약·계획 문서 작성만 수행합니다. 구현 파일 수정과 Notebook 코드 실행은 승인 뒤 진행합니다. 읽기 전용 자료 추출이 필요하면 원본을 보존하고 별도 작업 파일을 사용합니다.

| 실제 작업 | 먼저 읽을 지침 | 완료를 판단할 근거 |
|---|---|---|
| 현업자의 업무 정책이 불명확함 | hx-discover, stakeholder-questions, hx-plan | 실제 답변의 출처, 정상 사례, 예외 사례와 승인된 인수 조건 |
| CSV 집계 또는 테이블 조인 | hx-data, 필요하면 hx-specialist의 SQL 검토 | 행 수, 원본 ID, 빈 값, 중복 정책, 조인 전후 행 수와 결과 재조회 |
| PDF가 요구사항 또는 입력임 | 아래 PDF 절차 | 페이지 출처와 추출 범위, 읽지 못한 표와 이미지의 명시 |
| 기존 Notebook을 수정함 | 아래 Notebook 절차 | 새 커널에서 전체 실행한 결과와 저장된 산출물 재조회 |
| 웹 서비스를 구현함 | hx-plan의 API 설계, hx-specialist의 frontend-design | 실제 요청·응답 검사, 오류 처리와 사용자가 수행한 화면 확인의 구분 |
| 계산 또는 변환 규칙이 있음 | hx-build, hx-verify | 명세에서 정한 예시와 경계값, 규칙이 유지되는지 확인한 검사 |
| 기존 기능이 실패함 | hx-debug | 같은 입력으로 실패 재현, 원인 수정 후 동일 검사와 회귀 검사 |

## PDF 입력을 읽는 절차

1. 원본을 보존하고 파일명, 페이지 수와 읽을 범위를 기록합니다. 프로젝트에 이미 설치된 로컬 PDF 추출 도구가 있는지 확인합니다.
2. 텍스트 추출 도구가 있으면 별도 작업 파일로 추출합니다. 예를 들어 `pdftotext -layout input.pdf extracted.txt`는 해당 도구가 설치되어 있고 실행이 허용된 경우에만 사용합니다.
3. 페이지별 출처를 유지합니다. 표의 열 순서, 단위, 각주와 부등호가 텍스트 추출 과정에서 유실될 수 있습니다. 추출 결과만으로 이 항목을 확정하지 않습니다.
4. 스캔 문서, 비어 있는 추출 결과와 이미지에만 있는 규칙은 미확인으로 표시합니다. 허용된 로컬 OCR이 없으면 필요한 페이지의 내용을 사용자에게 확인합니다. 외부 OCR 서비스에 과제 파일을 보내지 않습니다.
5. 확인된 규칙만 명세에 연결합니다. 문서가 길다는 이유로 앞부분 표본을 전체 문서의 확인 결과로 표시하지 않습니다.

PDF 외부 스킬 원문은 포함하지만 PDF 패키지와 OCR 엔진은 포함하지 않습니다. 도구가 없으면 실행 불가와 영향을 기록합니다.

## Notebook을 다루는 절차

1. 원본 Notebook과 입력 데이터를 보존합니다. 셀의 코드, 저장된 출력과 실행 번호를 구분합니다. 저장된 출력은 현재 코드가 실행됐다는 증거가 아닙니다.
2. 기존 커널과 패키지를 확인합니다. 이미 `jupyter nbconvert`를 사용할 수 있고 실행이 허용되면 새 커널에서 전체 셀을 순서대로 실행합니다. 출력 Notebook은 별도 경로에 저장합니다.
3. 시간 제한을 정하고 실패한 셀을 기록합니다. 중간 셀만 실행해서 생긴 전역 변수에 의존하지 않습니다. 학습 데이터와 평가 데이터를 분리하고 변환 기준이 평가 데이터에서 학습되지 않았는지 확인합니다.
4. 생성한 CSV, JSON 또는 보고서 파일을 다시 읽습니다. 기대한 스키마, 행 수, 핵심 값과 빈 결과 여부를 검사합니다. 화면의 마지막 셀 출력만으로 저장 성공을 판정하지 않습니다.
5. 커널 또는 패키지가 없으면 무조건 새 환경을 만들지 않습니다. 허용된 기존 환경에서 가능한 검사를 수행하고 실행하지 못한 부분을 handoff에 기록합니다.

## 데이터 결과를 다시 읽는 기준

저장한 파일을 실제 소비자가 읽는 방법으로 다시 읽습니다. 식별자 `01`과 `1`의 구분, 날짜 기준, 인코딩, 소수 정밀도, 빈 값과 행 수를 확인합니다. 원문이 정하지 않은 중복 제거, 결측치 대체와 단위 변환은 먼저 질문합니다. 임의 입력을 생성하는 검사는 승인된 업무 규칙의 예시를 대체하지 않습니다.

## 남은 시간이 짧을 때

필수 기능과 실패 원인에 직접 필요한 지침만 읽습니다. 새 도구의 설치에 같은 원인으로 두 번 실패하면 기존 실행 환경으로 가능한 검사를 진행합니다. 요구사항, 승인과 실제 검증 근거는 생략하지 않습니다. 서술형 등 AI 사용 금지 단계에서는 이 절차도 중단합니다.

## 외부 스킬을 직접 선택하는 경로

[외부 스킬 선택표](external-routing.md)의 조건에 맞는 실제 파일을 읽습니다. 설치 후에는 문서에 적힌 경로 앞에 `.harness-kit/`를 붙입니다. 사용자에게 스킬 검색이나 선택을 요구하지 않습니다. 기술이나 업무 결과가 바뀌는 선택은 기존 계획 승인 절차를 따릅니다.
