# 업무 담당자 질문 양식

이 문서는 질문 예시입니다. 실제 질문에는 프로젝트 원문의 명사와 확인한 사실을 넣습니다. 이미 답이 있는 질문은 생략합니다. 한 번에 관련 질문 2~3개만 보내고, 답변에 따라 다음 질문을 고릅니다.

## 첫 묶음: 업무와 대표 사례

1. “이 결과물을 사용하는 사람은 누구이며, 어떤 일을 끝내려고 합니까?”
2. “실제 업무에서 자주 일어나는 사례 하나를 처음부터 결과 확인까지 설명해 주시겠습니까? 그때 들어오는 자료와 사람이 내리는 판단을 알고 싶습니다.”
3. “현재 방식에서 시간이 오래 걸리거나 잘못 처리되는 지점은 어디입니까?”

## 둘째 묶음: 예외와 우선순위

1. “대표 사례에서 입력이 없거나 중복되거나 서로 충돌하면, 담당자는 각각 어떻게 처리합니까? 실제로 가장 중요한 예외는 무엇입니까?”
2. “시간이 부족하면 반드시 동작해야 하는 경로를 어떤 순서로 확인해야 합니까? 이번 범위에서 제외해도 되는 경로는 무엇입니까?”
3. “자료를 제외하거나 보류해야 한다면 이유는 무엇입니까? 그 선택이 처리 전후의 건수나 결과에 어떤 차이를 만듭니까?”

## 셋째 묶음: 제약과 결정 권한

1. “기존 데이터 형식, 접근 권한, 보관 방식 또는 승인 절차 중 지켜야 할 조건은 무엇입니까?”
2. “이 처리 규칙과 범위를 최종 결정하는 사람은 누구입니까? 지금 답변 중 다른 사람의 확인이 필요한 부분은 무엇입니까?”
3. “원문과 방금 답변이 다르게 보이는 부분은 `[차이]`입니다. 어느 규칙이 현재 적용되며, 누가 이를 확인할 수 있습니까?”

## 넷째 묶음: 수용 기준과 재확인

1. “정상 입력 하나와 기대 결과를 구체적으로 제시해 주시겠습니까? 실패 입력에서는 무엇을 보여 주거나 기록해야 합니까?”
2. “완료한 결과를 누가 어떤 순서로 확인합니까? 통과와 보류를 가르는 관찰 가능한 기준은 무엇입니까?”
3. “제가 이해한 요구는 `[목표]`, `[입력과 기대 결과]`, `[중요한 예외]`, `[제외 범위]`입니다. 잘못 이해한 부분과 아직 결정되지 않은 부분을 알려주시겠습니까?”

답변자가 모르는 사항에는 같은 질문을 계속 반복하지 않습니다. 답변 가능한 범위와 결정 주체를 확인하고, 미확인 사항의 영향을 기록합니다. 담당자가 없는 작업에서는 이 문장을 보낸 것으로 기록하지 않습니다.

## 데이터나 상태 처리 과제에서만 추가할 질문

아래 질문을 한꺼번에 보내지 않습니다. 원문에 없고 결과를 바꾸는 질문만 고릅니다.

| 확인할 조건 | 사용자에게 전달할 질문 초안 |
|---|---|
| 용어와 단위 | “`[필드]`는 어떤 업무 값이며 단위는 무엇입니까? 빈 값과 0은 각각 무엇을 뜻합니까?” |
| 기준 시점 | “`[집계]`는 어느 시점과 기간을 기준으로 합니까? 날짜 경계와 시간대는 어떻게 정합니까?” |
| 비율 | “`[비율]`의 분자와 분모에 각각 어떤 자료를 포함합니까? 분모가 0이면 무엇을 표시합니까?” |
| 누적과 증분 | “이 파일은 전체 현황입니까, 이전 처리 뒤의 변경분입니까? 같은 자료를 다시 넣으면 어떻게 처리합니까?” |
| 상태 전이 | “`[상태 A]`에서 `[상태 B]`로 바뀌는 조건과 승인 주체는 누구입니까? 취소하거나 되돌릴 수 있습니까?” |
| 처리 전후 대조 | “제외 또는 병합된 자료를 사용자가 어떻게 확인해야 합니까? 입력 건수와 결과 건수가 달라지는 정상 사례를 알려주시겠습니까?” |

답변을 받은 뒤 업무 규칙, 정상 사례, 반례와 기대 결과를 [답변 기록](stakeholder-notes.md)에 연결합니다. 값을 정하는 주체와 프로그램을 조작하는 사용자가 다르면 역할을 구분합니다.
