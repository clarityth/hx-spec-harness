# HX Spec Harness

개발 과제의 업무 질문을 실제 동작과 검사 결과까지 연결하는 로컬 작업 도구입니다. Codex가 원문과 담당자 답변에서 요구를 정리하고, 승인된 계획에 따라 구현하고, 확인한 결과와 남은 문제를 `handoff.md`에 남기도록 안내합니다. Python 3.11 이상을 사용합니다.

## Codex CLI에서 바로 시작하기

현재 과제를 열어 둔 Codex CLI에 아래 문단을 보냅니다. 사용자가 폴더 경로나 JSON을 작성할 필요는 없습니다. Codex가 과제 폴더와 툴킷 폴더를 구분합니다.

> 현재 작업 중인 과제에 이 저장소를 clone해서 사용하고 `BOOTSTRAP.md`를 먼저 따르세요. 저장소 URL은 `https://github.com/clarityth/hx-spec-harness`이며, 툴킷은 과제와 별도 폴더에 두세요. 현재 세션과 파일에서 과제 폴더를 직접 확인하고 기존 파일을 보존하세요. 실제 원문과 담당자 답변을 바탕으로 필요한 질문, 계약과 계획을 작성하세요. 구현 전에 계획과 수용 기준을 제게 보여 주고 명시적 승인을 받으세요. 승인된 범위에서 구현, 검사와 인계를 진행하세요. 화면 확인과 최종 제출은 제가 직접 하겠습니다.

[Codex의 첫 실행](BOOTSTRAP.md)은 경로 확인, 설치와 기존 작업 재개를 안내합니다. 사용자가 직접 명령을 확인하려면 [시작 안내](START_HERE.md)를 읽습니다. 이 시작 지시는 계획 승인이 아닙니다.

## 한 과제가 진행되는 방식

1. **업무 질문을 확인합니다.** Codex가 원문에서 입력, 원하는 결과와 중요한 예외를 찾습니다. 결과를 바꾸는 내용이 불명확하면 사용자가 질문에 답하거나 허용된 채널에서 담당자 답변을 확인합니다.
2. **명세와 계획을 승인합니다.** Codex가 원문과 실제 답변을 계약과 계획에 연결하고, 구현 범위와 수용 기준을 보여 줍니다. 사용자가 계획을 명시적으로 승인합니다.
3. **작은 동작을 만들고 검증합니다.** Codex가 필수 경로를 먼저 구현하고 관련 검사를 실행합니다. 검사 결과와 사용자의 화면 확인을 구분합니다.
4. **결과를 인계합니다.** Codex가 실행법, 선택 이유, 실제 검사와 미확인을 `handoff.md`에 적습니다. 사용자가 제출 파일을 확인하고 직접 제출합니다.

[한 과제를 끝내는 운영 순서](docs/session-playbook.md)는 각 단계에서 만들 결과와 다음 단계로 넘어갈 기준을 설명합니다. 계획이나 원문이 바뀌면 수정한 계획을 다시 승인받습니다.

## 작업 후 확인할 결과

- `.harness/contract.json`에는 실제 요구와 기대 결과의 근거가 남습니다.
- `.harness/plan.json`에는 승인받을 범위와 검사 방법이 남습니다.
- `.harness/evidence/`에는 실행한 검사의 결과가 남습니다.
- `handoff.md`에는 실행법, 실제 결과와 미확인 항목이 남습니다.

## 사용자와 Codex의 역할

| 사용자 | Codex |
|---|---|
| 화면에만 있는 원문과 담당자 답변을 허용된 방법으로 전달합니다. | 프로젝트 원문과 기존 파일을 읽고 필요한 질문을 정리합니다. |
| 결과를 바꾸는 선택에 답하고 실제 계획을 승인합니다. | 계약과 계획을 작성하고 승인된 범위에서 구현합니다. |
| 허용된 화면에서 동작을 확인하고 직접 제출합니다. | 실행한 검사, 결과와 남은 문제를 인계합니다. |

## 작업에 맞춰 쓰는 스킬

자체 스킬은 시작, 요구 확인, 계획, 구현, 데이터 점검, 디버깅, 검증, 설명과 인계를 연결합니다. 외부 원문 12개는 해당 작업이 있을 때 선택해 읽도록 안내합니다. 스킬을 포함했다는 사실만으로 자동 실행이나 품질 향상을 보증하지 않습니다.

| 작업 | 참고하는 외부 원문의 목적 |
|---|---|
| 요구와 API 계약 | 업무 범위와 제약을 정리하고 실제 요청·응답과 오류 계약을 설계합니다. |
| React 상태 처리 | 실제 버전과 문제 조건에 맞는 동시성·배칭 원문을 읽습니다. 버전 이주를 강요하지 않습니다. |
| 계획과 구현 | 계획을 실행 순서로 나누고, 의미 있는 동작에는 작은 기대값과 검사를 정합니다. |
| 오류와 완료 확인 | 원인을 재현해 수정하고, 완료 보고 전에 실제 실행 근거를 확인합니다. |
| 웹 화면과 SQL | 화면 설계를 검토하고, SQL의 조인·집계·NULL 처리를 점검합니다. |
| 명시적 보안 요청과 기존 코드 | 적용 기술의 보안 지침을 확인하고, 변경 범위의 검사 공백을 찾습니다. |

[스킬 목록](docs/skill-catalog.md)에 포함된 원문과 적용 조건이 있습니다. 한국어 문서 작성에는 포함된 fluent-korean 원문을 참고합니다.

## 더 읽을 문서

[검증 결과와 설계 근거](docs/validation.md)에서 실제 실행으로 확인한 범위와 참고한 공개 자료를 볼 수 있습니다.
