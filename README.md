# HX Harness · SK하이닉스 해커톤 준비 툴킷

**현업자의 요구를 질문으로 파악하고, Codex와 구현한 결과를 본인 말로 설명하기 위한 개발 툴킷입니다.**

SK하이닉스 해커톤의 Cofa 환경에서 사용할 목적으로 준비했습니다. 과제를 받으면 Codex가 필요한 개발 스킬을 찾아 읽고, 요구사항 정리부터 설계, 구현, 검증과 인계까지 이어갑니다. 참가자는 업무상 중요한 판단을 내리고 구현 내용을 이해하는 데 집중합니다. SK하이닉스나 Cofa가 제작하거나 인증한 도구는 아닙니다.

## 왜 만들었나요?

제한 시간 안에 과제를 수행하면서 개발 스킬을 검색하고, 사용할 도구를 설치하고, 작업 순서를 다시 정하면 구현에 쓸 시간이 줄어듭니다. AI가 만든 코드의 동작과 선택 이유를 이해하지 못하면 후속 서술형에서도 설명하기 어렵습니다.

이 저장소에는 그 준비 작업에 필요한 자료를 모았습니다.

- **업무 질문:** 원문과 현업자 답변에서 목표, 입력, 처리 규칙과 예외를 확인합니다.
- **설계와 구현:** 명세를 먼저 정하고, 승인한 계획에 따라 작은 기능부터 구현합니다.
- **외부 개발 스킬:** 설계, 언어·프레임워크, TDD, 디버깅, 리뷰, 데이터와 UI 자료를 동봉했습니다.
- **검증과 설명:** 실제 검사 결과와 코드 경로, 선택 이유, 남은 한계를 `handoff.md`로 연결합니다.

## 시작하기

Cofa의 실제 과제 폴더를 열어 둔 Codex CLI에 아래 문장을 전달합니다.

> SK하이닉스 해커톤 과제를 진행합니다. https://github.com/clarityth/hx-spec-harness 를 과제와 별도 폴더에 clone하고 BOOTSTRAP.md를 따르세요. 기존 파일과 과제 원문을 먼저 확인하세요. 제공된 현업자 대화가 있으면 제가 전달한 실제 답변을 요구사항에 연결하고, 모호한 정책은 질문으로 정리하세요. 필요한 개발 스킬은 동봉 선택표와 색인에서 직접 찾아 읽으세요. 설계와 구현 계획을 제게 보여 주고 명시적 승인 후 구현·검사·리뷰를 진행하세요. 제가 핵심 동작과 선택 이유를 이해할 수 있게 설명하고, 실제 근거를 handoff.md에 남기세요. 현업자에게 질문 전달, 화면 확인과 최종 제출은 제가 직접 합니다. 현재 과제의 공식 규정을 우선하세요.

Codex가 과제 폴더와 툴킷 폴더를 구분하고 설치합니다. 사용자가 JSON이나 스킬 경로를 직접 작성할 필요는 없습니다. 위 시작 요청은 실제 구현 계획의 승인을 대신하지 않습니다.

설치 도구에는 Python 3.11 이상이 필요합니다. 기존 환경을 바꾸지 않고 사용할 수 있는지 먼저 확인합니다. 설치가 어려우면 [BOOTSTRAP](BOOTSTRAP.md)의 문서 기반 진행 절차를 따릅니다.

## 과제 하나를 진행하는 흐름

| 단계 | Codex가 준비하는 것 | 참가자가 확인하거나 결정하는 것 |
|---|---|---|
| **1. 업무 파악** | 원문에서 확정된 사실과 미확인 정책을 구분하고 현업자에게 물을 질문을 작성합니다. | 허용된 대화 채널에서 질문하고 실제 답변을 전달합니다. |
| **2. 명세와 설계** | 입력·출력·예외와 인수 조건을 정리합니다. 구조와 기술의 대안, 선택 이유와 비용을 설명합니다. | 업무 정책과 결과를 바꾸는 선택을 결정하고 계획을 승인합니다. |
| **3. 구현** | 승인한 범위에서 핵심 동작부터 구현합니다. 계산·분기·회귀 수정에는 의미 있는 테스트를 먼저 확인합니다. | 중요한 선택이 무엇이며 입력이 어떻게 결과로 바뀌는지 이해합니다. |
| **4. 검증과 리뷰** | 실제 명령을 실행하고 요구사항별 결과를 대조합니다. 실패를 재현하고 수정하며 미확인 항목을 남깁니다. | 허용된 미리보기에서 필요한 화면 동작을 직접 확인합니다. |
| **5. 인계와 제출** | 실행법, 주요 코드, 선택 이유, 검사 근거와 남은 문제를 `handoff.md`에 정리합니다. | 제출할 파일과 상태를 확인하고 직접 제출합니다. |
| **6. 후속 서술형** | AI 사용이 금지되는 단계에서는 지원을 중단합니다. | 구현 중 이해한 내용과 실제 판단을 본인 말로 작성합니다. |

현업자 채널의 제공 여부, 제한 시간과 제출 형식은 실제 과제 안내로 확인합니다. 존재하지 않는 담당자 답변이나 사용자의 관찰을 만들어 기록하지 않습니다.

## 개발 스킬은 미리 준비했습니다

기본 작업에는 27개 외부 스킬을 연결했습니다. 다른 기술이 필요하면 확장 라이브러리를 로컬에서 검색합니다. 동봉된 `SKILL.md`는 **153개**, 같은 출처·판본·내용의 중복 1개를 제외하면 **152개**입니다. 이 수치는 자료의 수이며 성능 측정값이 아닙니다.

| 필요한 작업 | 포함한 주요 자료 |
|---|---|
| 아키텍처와 데이터 설계 | proyecto26의 system-design, service-decomposition, data-storage와 Jeffallan의 architecture-designer 및 기술별 설계 자료 |
| 명세와 계획 | Superpowers의 brainstorming·writing-plans·executing-plans, Addy Osmani의 spec-driven-development |
| 구현과 오류 해결 | Superpowers의 TDD·디버깅·리뷰, Matt Pocock의 엔지니어링 자료, Jeffallan의 언어·프레임워크별 스킬 |
| 현업 용어와 설계 결정 | Matt Pocock의 domain-modeling과 관련 서식, 문서·ADR 작성 자료 |
| 화면과 접근성 | frontend-design, UI UX Pro Max의 검색 코드와 데이터, Impeccable의 디자인 참고 자료 |
| 데이터와 문서 | SQL 검토, 속성 기반 테스트, OpenAI의 PDF·Jupyter Notebook 자료 |
| 코드 단순화와 품질 | Addy Osmani와 Ponytail의 검토 자료 |

[기본 선택표](docs/external-routing.md)와 [전체 스킬 색인](docs/external-library.md)에 실제 파일 경로와 적용 조건이 있습니다. Codex가 필요한 원문과 참조만 읽습니다. 전체 스킬을 한꺼번에 실행하거나 프로젝트 설정에 등록하지 않습니다.

추가 자료가 필요할 때 Codex가 사용하는 로컬 검색 명령입니다.

```sh
python3 .harness-kit/tools/find_external_skills.py "아키텍처"
python3 .harness-kit/tools/find_external_skills.py "react testing"
```

자동 브라우저 조작이나 외부 게시 등 현재 규정에 맞지 않는 절차는 기본 검색에서 제외합니다. 포함한 파일의 출처, 고정 커밋과 라이선스는 [제3자 고지](NOTICE.md)에 있습니다. 자체 hx 지침 11개는 승인, 파일 경로와 기록을 연결하는 역할입니다.

## 마지막에 무엇이 남나요?

가장 먼저 읽을 결과물은 **`handoff.md`**입니다.

- 무엇을 구현했고 어떻게 실행하는지 설명합니다.
- 입력이 어떤 파일과 함수를 거쳐 출력으로 바뀌는지 설명합니다.
- 어떤 대안을 비교했고 왜 현재 방법을 선택했는지 남깁니다.
- 무엇을 실제로 검사했고 무엇이 아직 확인되지 않았는지 구분합니다.
- 작업을 이어갈 경우 현재 상태와 다음 행동을 알려 줍니다.

Codex는 요구사항과 승인 계획을 `.harness/contract.json`, `.harness/plan.json`에 기록하고 검사 근거를 `.harness/evidence/`에 남깁니다. 코드가 바뀐 뒤 이전 검사 결과를 현재 통과로 사용하지 않는지 확인합니다. 공식 제출 파일은 과제 안내를 따릅니다.

인계 문서를 만들었다고 참가자가 구현을 이해한 것으로 처리하지 않습니다. 구현 중 핵심 동작, 선택 이유와 검증 결과를 설명하고 함께 확인하는 과정이 필요합니다.
