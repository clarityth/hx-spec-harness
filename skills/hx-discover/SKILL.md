# 업무 요구 발견

업무 목표, 입력과 출력, 예외 처리 또는 완료 조건이 불명확할 때 이 스킬을 사용합니다. 먼저 프로젝트 원문과 적용 지침을 읽습니다. 작업 공간의 `.harness-kit/GUARDRAILS.md`, `.harness-kit/docs/discovery.md`와 `.harness-kit/templates/stakeholder-questions.md`를 확인합니다.

1. 원문에 이미 있는 사실과 결과를 바꾸는 빈칸을 나눕니다. 질문 가능 채널과 답변자의 권한을 확인합니다. 채널이 없으면 담당자 답변을 만들어 내지 않습니다.
2. 실제 사례에서 시작해 한 번에 관련 질문 2~3개를 작성해 사용자에게 전달합니다. 사용자가 허용된 채널에서 직접 질문합니다. 명시적으로 허용되지 않은 자동 메시지 전송과 UI 조작은 하지 않습니다. 답변에 따라 예외, 우선순위, 제약, 결정 주체와 수용 기준을 묻습니다. 같은 질문을 반복해 원하는 답을 유도하지 않습니다.
3. 작업 공간의 `.harness-kit/templates/stakeholder-notes.md`를 읽기 전용 양식으로 참고합니다. 과제가 지정한 기록 경로가 없으면 프로젝트 루트의 `stakeholder-notes.md`에 실제 질문, 답변의 짧은 원문, 위치, 발화자, 확정 여부와 남은 충돌을 적습니다. 런타임의 양식 원본에는 답변을 쓰지 않습니다. AI가 제안한 내용을 담당자의 답변으로 표시하지 않습니다.
4. 확인된 요구를 `R` ID, 작은 입력과 기대 결과, `C` 검사 ID로 연결합니다. 미확인 정책은 계획의 열린 질문에 영향과 선택지를 적습니다. 답변을 받기 전에는 `answered`로 바꾸지 않습니다.
5. 담당자에게 이해한 내용을 짧게 재확인합니다. 요구와 계획을 사용자에게 제시하고, [hx-plan](../hx-plan/SKILL.md)에 따라 구현 전 명시적 승인을 받습니다.

완료 조건은 핵심 사례와 중요한 예외의 출처, 결정 주체, 수용 기준, 검증 방법이 연결된 상태입니다. 답변하지 못한 부분과 상충하는 답변은 그대로 남깁니다. 양식을 채운 사실만으로 요구가 확정되거나 구현이 승인되지는 않습니다.

실제 답변으로 업무 용어가 확정되면 `.harness-kit/third_party/mattpocock-domain/skills/engineering/domain-modeling/SKILL.md`를 읽습니다. 가상 반례는 확인 질문이며 실제 업무 정책으로 기록하지 않습니다.
