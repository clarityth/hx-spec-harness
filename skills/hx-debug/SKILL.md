# 오류 원인 확인과 수정

현재 plan과 status를 읽습니다. 승인이 무효이면 추가 실행 전에 hx-plan으로 돌아갑니다. `.harness-kit/docs/upstream-policy.md`와 `.harness-kit/third_party/obra-superpowers/skills/systematic-debugging/SKILL.md`를 읽습니다. 원문이 연결한 원인 추적과 검증 문서는 해당 기법이 필요할 때만 읽습니다.

실패한 입력, 기대값, 실제 출력과 로그로 재현 조건을 확인합니다. 코드의 추정 원인과 관찰한 사실을 구분합니다. 가장 작은 변경으로 가설을 확인하고 같은 기대값으로 관련 검사를 실행합니다. 실행 오류를 기능 회귀 실패로 바꾸어 서술하지 않습니다.

원문과 수용 기준은 구현에 맞춰 완화하지 않습니다. 요구 해석을 바꿔야 하면 근거와 선택지를 제시해 먼저 질문합니다. 같은 원인으로 수정이 반복 실패하면 가설과 구조를 재검토합니다. 보고를 위해 가짜 실패를 만들지 않습니다. 연습용 변이를 넣었다면 그 사실을 표시합니다.
